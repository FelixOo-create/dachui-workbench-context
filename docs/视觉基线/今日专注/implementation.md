# 今日专注实施基线

## 基线文件

- `approved-default.png`：今日专注主状态，1920×1080。

该图片是本轮真实落地的视觉基线。目标是把原来的独立时间块页面改造成“番茄钟驱动的一日专注总结”，不再以手工填写全天网格为主流程。

## 必须匹配的视觉方向

- 保留工作台现有顶部场景导航、标题骨架和底部工具栏；内容采用左侧番茄钟/时间流、右侧指标/今日总结的双栏结构。
- 使用近黑、低饱和炭灰材质，搭配薄荷绿、钢蓝和少量暖金；卡片使用细边框、轻透明和克制柔光。
- 1920×1080 下应接近基线的信息密度、字号层级、边距与对齐：细密时间柱、四张横向指标卡、放大的环形分布图及充分利用的总结卡空间。
- 不回退到粗柱、大面积空白、小字号或原有全天手工时间格栅。

## 页面固定骨架统一

- 只以已经完成且彼此一致的习惯和纪念册页面为页面级标准，优先对照 `HabitsSceneV2.css` 的 `.habits-v2-root` / `.h2v2-scene-heading` 与 `MemoryJournal.css` 的 `.memory-v2-page` / `.memory-v2-heading`。待办页面和当前今日专注页面均不是这一项的参照，不得用两者反向确定边距或标题位置。
- 今日专注根容器使用现有 DesktopShell 内容区，不重复增加整页外边距或第二层壳；页面头固定为 `76px`，页面头与首个内容板块间距为 `14px`。
- 标题区左右内缩 `5px`，底部对齐；主标题上边距 `3px`、字号 `31px`、行高 `1.05`、字重约 `660`、字距 `-.04em`；英文眉题字号 `10px`、字重 `750`、字距 `.13em`；副标题上边距 `7px`、字号 `12px`。
- 右侧页面操作区底部内缩 `2px`、控件间距 `9px`，按钮高度、圆角和颜色沿用已完成页面的同级控件。首排卡片必须与标题区及其他页面处在相同水平锚点。
- 当前今日专注标题左侧额外的薄荷绿竖线不属于习惯/纪念册共同骨架，应移除；不要用装饰线补偿错误的标题内缩。
- 按习惯和纪念册根容器的实际内容范围统一左、右、上、下边界，消除截图标出的额外左右留白和内容宽度偏差；标题区、首排卡片、下排卡片必须共享同一左右内容边界。
- 外层间距必须由且仅由一层容器负责：常规窗口使用与习惯容器、纪念册场景包装一致的 `padding: 14px 18px 18px`，对应窄屏使用 `10px 12px 12px`；不得同时在场景包装和页面根节点重复添加。
- 今日专注页面根节点必须保持透明，不得设置独立的 `--wb-bg-deep` 或其他不透明整页背景；工作台壁纸应像习惯、纪念册一样连续显示，不得形成顶部黑色横块或底部黑色边带。
- 页面根节点应在统一内容框内 `height: 100%`、`min-height: 0`、`overflow: hidden`；主体网格必须填满页面头以下的可用空间，不使用会让总高度由子内容自行撑开的 `height: auto`。仅真正需要滚动的内部列表自行滚动。
- 如已有共享样式可安全复用则直接复用；否则仅在今日专注作用域内按相同令牌实现。不得为了统一这一页而批量重构或改变习惯、纪念册的现有布局。

## 必须保留和接入的真实能力

- 复用原时间块已有的分类/活动标签信息和存储，不新建第二套标签体系，不迁移或破坏既有历史记录。
- 番茄开始前选择一个现有标签；正常完成后自动把实际专注区间写入同一套时间记录。用户主动“结束并保存”时保存实际有效专注时长；暂停时间不计入，重置或取消不生成记录。
- 原有历史时间块与番茄自动记录共同显示在一日时间流和标签统计中；“补记一段”仅作为次要入口，并继续使用相同标签。
- 今日有效专注、完成番茄、最长专注时段、番茄完成率、标签投入分布和番茄长度表现必须由真实记录计算，不得硬编码预览数字。
- 旧记录缺少番茄来源字段时按手工记录兼容展示；不得要求用户清空或重建数据。

## 关键交互规则

1. 番茄开始、暂停、恢复、正常完成、提前结束保存、重置与页面恢复必须保持一致状态；写入失败要明确反馈且不可静默丢失记录。
2. 标签选择与原时间块标签保持单一来源；删除或变更标签时沿用现有数据规则，不创建孤立的番茄专用标签。

## 可调整范围

- 可根据真实组件和窗口宽度微调卡片间距、柱状图采样密度、文字换行和图标，但 1920×1080 主状态的布局、层级和空间利用需接近基线。
- 预览中的示例事项、时间与统计数字仅为结构示例，实施必须使用隔离测试数据或真实接口返回值。
- 如果现有数据模型无法无损表达某项派生统计，可在不影响主链路的前提下调整该项展示，但必须说明口径与限制。

## 不应带入

- 不加入装饰性名言、绿植、虚构智能点评或无法从现有数据验证的效率结论。
- 不恢复独立的手工时间块主页面，也不扩大到日程、待办、习惯或其他模块重构。

## 验收门槛

- 功能：覆盖标签复用、完成自动写入、提前结束保存、暂停排除、重置不写入、历史记录兼容与统计刷新；运行 `npm run typecheck`、`npm run test`。
- 构建：本次涉及主进程计时服务、IPC、日程存储与 Renderer，完成后运行 `npm run package`。
- 视觉：使用隔离测试数据在 1920×1080 截取真实页面，与 `approved-default.png` 对照布局、字体、对齐、间距、图表密度和内容空间利用。
- 页面一致性：在相同 1920×1080 窗口下分别与习惯、纪念册真实页面对照，核验根内容区域四边范围、标题左边界、标题基线、副标题、右侧操作区、内容起始线、左右边距及底部留白；不得用待办页面作为通过依据。
- 几何证据：除截图外，输出三个真实页面根容器、页面头和主体区域的 `x / y / width / height`；今日专注与习惯、纪念册共同边界的误差应控制在 1–2px，不能只凭目测宣布一致。
- 交付时分别报告功能正确性与视觉还原度，并列出无法一致的真实限制；不得读取真实数据库内容、日志、密钥或用户隐私数据。
