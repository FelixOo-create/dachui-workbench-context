## 本阶段目标

把原先由多个独立工具、入口页和旧工作台页面组成的系统，收口成一个 Windows 本地工作台：它在视觉上模拟桌面，在同一窗口内承载完整功能页，并允许独立工具继续通过统一入口启动。与此同时，以“先做可落地预览、用户确认、再接真实业务”的方式逐页重做核心模块。

当前方向不是绑定 Explorer 的真实桌面组件，也不是把所有子工具源码强行吸收到一个进程；而是一个统一的 Electron 桌面壳层，内部模块直接渲染，复杂外部工具保持独立运行和独立迭代。

## 已完成的产品收口

### 1. 外部工具退役与依赖收口

- 独立“日程&待办工具”已退役，待办、时间块和习惯改用 Workbench 自身的日程数据库与页面，不再依赖原外部路径。
- 独立“书签页工具”已退役；当前书签实现固定在 `modules\bookmarks`，用户数据位于 Electron `userData`，旧项目只保留离线归档。
- 原外部项目 Check、RedNote工作台、无限画布和 Tooler 仍由各自项目拥有；Workbench 只提供统一入口，不吸收或移动其源码。
- 纪念册在线封面 API 路径已封存，正式方案为剪贴板粘贴、本地图片选择或无封面保存，不恢复 TMDB Token 配置。

### 2. Windows 工作台架构

- 正式形态为普通无边框 Electron 窗口铺满目标显示器 `workArea`，保留 Windows 任务栏；不是 Explorer 桌面层，也不承诺按 `Win+D` 后仍留在真实桌面上。
- 支持显示器选择、显示器断开后回退、托盘隐藏/恢复、单实例、快捷键和正式 EXE/ZIP 产物。
- 顶部保留场景导航；底部 Dock 统一承担工具入口、固定工具、布局、设置和时钟。顶部不再重复放置工具中心入口。
- 核心场景为今日、待办、时间块、习惯、记录册、画布和工具；成熟模块在当前主内容区直接呈现，不再显示“打开页面”式入口卡片。

### 3. 首页与工具组织

- 首页支持组件清单、显示器级布局保存、智能填充、二分、三分、四宫格、主次和自由布局，并保留一次撤销。
- 桌面文件和软件只做镜像卡片，不移动、删除或重命名原始文件；使用原始 Windows 图标。
- 工具中心支持搜索、状态/分类筛选、启动停止、扫描、添加编辑、移除注册和 BAT 随工作台启动管理。
- 未完成或不能可靠运行的首页功能不应以假入口占位；天气等配置必须有真实设置路径后才作为正式能力保留。

## 统一设计与实施方式

### 当前设计语言

- 近黑、低饱和炭灰体系，少量薄荷绿和暖金状态色，不以蓝紫为主色。
- 卡片采用轻透明、细边框、局部柔光和克制阴影；弹窗、菜单和悬浮层可使用更明显的毛玻璃。
- 页面层级、按钮密度和空状态必须经过真实运行截图验收，不能只靠 CSS 名称或静态概念图判断。
- 页面外壳统一以当前习惯页为标准：标题左边线、顶部位置、内容最大宽度、左右边距和底部留白一致；页面最外层不再增加覆盖整页的大框，只给真实内容面板设置边框。

### 预览优先流程

- 当前主对话负责需求讨论和快速可落地预览；预览用共享 HTML/CSS 结构和隔离 fixture 渲染，不使用生图伪造产品界面。
- 用户明确确认后，把图片和精简实现约束冻结到 `docs\视觉基线\<页面>`；实施对话只读取该基线并连接真实业务。
- 功能验收和视觉验收是两道独立门槛：静态预览不能证明业务可用，测试通过也不能证明视觉一致。
- 已配置本地 `ui-preview-handoff` Skill。无参考图也可正常使用；用户提供参考时，只把它作为布局、材质或细节映射，不直接要求像素照抄不可落地效果。
